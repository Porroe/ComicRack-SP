# ComicRack SP developer handoff

## Build and install

Open the Android project root in Android Studio. Use JDK 17, the included Gradle 9.6.0 wrapper, Android Gradle Plugin 9.4.1, Android SDK Platform 37, and Build Tools 37.0.0. The app ID is `com.cyo.comicracksp`. The minimum SDK is 26 and the compile and target SDK are both 37. The Java source build uses Material Components for Android 1.13.0 for the library and Settings, Junrar 8.1.2 for CBR extraction and `desugar_jdk_libs_nio` 2.1.5.

```sh
./gradlew :app:assembleSourceDebug
adb install -r app/build/outputs/apk/source/debug/app-source-debug.apk
```

Keep the signing keystore in durable storage. Android requires the same signing key to update an existing installation. A regenerated debug key requires a separate test application ID or a fresh install.

## Source recovery

- `app/src/main/java` is based on JADX 1.5.2 output produced with `--deobf --no-inline-methods --no-inline-anonymous`. Compare the original names in `renamed from` comments with Smali when a method looks incomplete or its control flow looks suspicious.
- The manifest and resources came from Apktool. Keep surviving IDs in [stable-resource-ids.txt](../app/stable-resource-ids.txt) aligned with the resources because recovered classes still use numeric constants. The original APK, decoded Smali, and rebuilt APKs are local reference artifacts. The Gradle build uses checked-in source and resources.
- Recovery work covered reader lifecycle and layout, page scaling and animation, archive detection and extraction, metadata, bitmap caching, and library grouping. CFR and Vineflower output from a dex2jar conversion helped cross-check the Java. The legacy Wi-Fi socket dispatcher was translated from Smali.
- Give classes, methods, parameters, and variables descriptive names as their roles become clear. For an eventual Kotlin migration, use Java and Kotlin side by side in the app module and compare each migrated component against the working Java build and original Smali.

## Storage and library

- [ComicDocuments.java](../app/src/main/java/com/cyo/comicrack/storage/ComicDocuments.java) handles Storage Access Framework document trees and individual comics. Folder selection persists read grants and stores tree URIs in preferences. The scanner queries child documents and opens archives via content URIs. Reselect a folder if its grant is revoked. Keep network-backed or slow document providers in mind when touching this path.
- [ArchiveCache.java](../app/src/main/java/com/cyo/comicrack/storage/ArchiveCache.java) stages document archives in app-private cache for readers that need seekable files. It enforces a 1 GiB size limit and seven-day idle expiration. The cover thumbnail cache is separate and reuses thumbnails across launches. Reading progress and metadata continue to use the existing SQLite database.
- [ComicRackApplication.java](../app/src/main/java/com/cyo/comicrack/viewer/ComicRackApplication.java) builds the startup library from SQLite records for folders with valid read grants, then schedules a background scan. [LibraryRefreshTask.java](../app/src/main/java/com/cyo/comicrack/viewer/LibraryRefreshTask.java) runs the scan with the existing weighted phases (75/25). [LibraryRefreshController.java](../app/src/main/java/com/cyo/comicrack/viewer/LibraryRefreshController.java) owns progress and failure state at application scope, attaches only to the resumed activity, and dismisses old dialogs on detach. Manual refresh shows real progress and Retry/Close on failure; startup scans remain silent. Keep the saved library usable when a provider is slow. Room and migration from the original app are deferred.
- [SplashActivity.java](../app/src/main/java/com/cyo/comicrack/viewer/SplashActivity.java) starts library initialization directly, and the first launch skips automatic About. The usage-statistics prompt and its startup scheduling were removed. Reader close/next actions run their continuation immediately; only explicit manual rating opens the rating dialog. The automatic-rating preference was removed. The empty-folder prompt uses MaterialAlertDialogBuilder in both interfaces and keeps folder selection and suppression behavior. Settings opens About; Classic also retains its About menu entry.
- [SystemBarInsets.java](../app/src/main/java/com/cyo/comicrack/viewer/SystemBarInsets.java) applies modern system bar insets to legacy layouts. Twitter integration was removed, including its settings, entry points, resources, and bundled Twitter4J code. Legacy Wi-Fi sync still assumes a writable filesystem path and is outside the document-tree flow.

## Library and Settings UI

- [LibraryInterface.java](../app/src/main/java/com/cyo/comicrack/viewer/LibraryInterface.java) applies Material 3 library styling to the existing activities and adapters. Material is the default. **Settings → Library interface → Classic** stores the opt-in in the shared `classic_library_interface` preference. Library activities recreate when returning from Settings after the choice changes. The reader uses its existing layout in either mode.
- [LibraryCollectionSheet.java](../app/src/main/java/com/cyo/comicrack/viewer/LibraryCollectionSheet.java) replaces the Material drawer and pin controls. Its Browse/Collections/Past Searches tabs reuse the existing collection hierarchy and search history. Browse root icons are chosen from the stable category IDs, independently of translated labels: Series/library_books, Stories/auto_stories, Folders/folder_open, Publishers/business, Years/calendar_month, Writers/edit, Artists/palette, and Genres/category. Recycled rows bind their own icon resource; nested collections keep stacked cover previews. The six added vectors come from Google Material Symbols Outlined, except business from the official Material Icons Outlined set, under the existing Apache 2.0 notice. A standard `TextInputEditText` above the tabs searches the whole library without opening the keyboard automatically. Clear restores **All comics** and retains history; selecting a collection clears the query and closes the sheet. Material keeps the existing navigation fragment in a hidden container as its data controller. Classic retains its original layout and navigation. Its pin button is available when the actual sidebar/pager layout supports pinning, rather than depending solely on the screen-size classification. The Material sheet opens at 60% height and expands by dragging; a nested-scrolling RecyclerView recycles 112 dp collection rows with up to three Classic-style covers. Thumbnail bindings and bitmaps are cleared on reuse. Material hides the duplicate grid caption except when the stack-close control is needed. The collection sheet has no X button; standard bottom-sheet dismissal remains available.
- `LibraryCollectionPageListener` synchronizes the visible pager collection with the Material toolbar title/issue count and the legacy sidebar selection. `ComicListActivity` also updates the toolbar in its page callback. Resolve the collection from the selected page index rather than relying on the previously displayed fragment. The recovered ViewPager now uses floating-point normalization for page positions and margins, including negative offsets created when an initially selected middle/last page is anchored at zero. Integer division previously caused backward drags to snap back. Material pager controllers do not retain the legacy PagerTabStrip; Classic retains its tab behavior. [MaterialCollectionTabs.java](../app/src/main/java/com/cyo/comicrack/viewer/MaterialCollectionTabs.java) bridges the recovered pager to a bottom-aligned Material secondary TabLayout. It observes adapter changes, synchronizes labels and selection without callback loops, shows on drag/tab interaction, and hides three seconds after interaction settles. Another swipe resets the timer; rows with at most one collection stay hidden. The row reserves its own height above system navigation while visible and releases that space while hidden. Detaching the pager removes the hide callback and adapter observer.
- The separate [LibraryOptionsSheet.java](../app/src/main/java/com/cyo/comicrack/viewer/LibraryOptionsSheet.java) provides Filter, Sort, and Display tabs using the existing per-list settings and grouping logic. Filter uses a rounded card of full-width single-selection Material radio rows (All/Unread/Reading/Read), sharing the Sort by card and row helpers. Sort places ascending/descending segmented buttons above grouped radio choices. Display uses icon segments for Cover/Detail/Stack, a grouped Compact view switch, and conditional stack grouping. The sheet expands by dragging and keeps its title/tabs above nested-scrolling content. The five new view/direction vectors use official [Google Material Icons](https://github.com/google/material-design-icons), with the existing Apache 2.0 notice. Changes apply immediately and save the config preference. Material stack groups honor the ascending/descending choice.
- Continue Reading uses the recently opened collection and the comic’s metadata formatter (including issue number), with the saved page on a separate line. It loads the cover through the same asynchronous thumbnail path as the grid and hides the card when there is no recent comic. The X button and standard `SwipeDismissBehavior` (either direction) share one dismissal handler, which stores the dismissed comic ID in `dismissed_resume_comic`. A different most-recent comic clears that dismissal. Both library layouts share comic records and reading progress.
- [ComicRackPreferencesActivity.java](../app/src/main/java/com/cyo/comicrack/viewer/ComicRackPreferencesActivity.java) hosts the existing preference groups and folder picker in a Material 3 Settings activity. The library and Settings use [Google Material Symbols Outlined](https://github.com/google/material-design-icons/tree/master/symbols/web) under the [Apache 2.0 license](material-symbols-license.txt). The wider tablet series-detail pane is still pending. [AboutDialog.java](../app/src/main/java/com/cyo/comicrack/viewer/AboutDialog.java) provides shared Material About/History tabs, original rich-text credits and links, Help, and Close. It unregisters lifecycle callbacks and dismisses its window when its owning activity is destroyed. Other secondary dialogs retain existing Android controls.

## Device checks

Use a clean test install for first-launch checks and a populated library for scan and cache checks. Keep the user's existing library data intact when testing.

1. Confirm startup reaches the folder prompt without showing About or Terms. Select a folder and reopen the app to check that the grant persists.
2. Open a CBZ and a CBR from the library and through Android’s file manager. Turn a page, drag to preview the next page, then reopen a comic and check its saved position.
3. Open the Material Collections sheet; check Browse/Collections/Past Searches and category back navigation. Confirm the keyboard stays closed until the search field is tapped. Submit a query, replay history, clear it, and confirm **All comics** returns while history remains. Verify the cover, issue number, and separate page line in Continue Reading.
4. Exercise every bottom-sheet tab, sort direction, stack grouping, and Compact view. Check that selections survive a restart. Expand/collapse the collection sheet and repeatedly scroll a long Series list in both directions; confirm recycled cover previews match their labels. Swipe between collections with different issue counts and check the toolbar. Dismiss Continue Reading with X and swipes in both directions, restart, then open another comic to verify it returns. Switch between Material and Classic. Reopen Settings and verify that the choice persists. Check cover reuse after a restart and that refresh picks up folder changes.
5. Check About/History, Help, Close, and normal dismissal. Recreate the activity during manual refresh and verify progress survives without retaining the old dialog; check failure Retry/Close.
6. Exercise folder reselection after losing access and use a sizable library when checking scan performance.

The original recovery pass exercised stored, compressed, and solid RAR4 fixtures and CBZ reading on Android 14. Later Android 16 tablet checks covered the scoped-storage library, cover reuse across restart, Stack view switching, and first launch without About or Terms. Record the device, Android version, and archive types for new checks. RAR5, Wi-Fi sync, and a full compatibility matrix remain unverified.

The collection-sheet pass on the Android 16 tablet checked search/history replay, clearing, category selection, and About/History. An external instrumentation harness verified refresh progress across activity recreation and injected a controller failure before retrying a real scan. The harness is not part of the app.
